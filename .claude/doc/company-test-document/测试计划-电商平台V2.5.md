### 1.2 系统概述

本项目为电商平台日常迭代版本，主要涉及以下模块：
- **商品管理**：商品上下架逻辑优化、SKU 批量导入性能提升
- **订单中心**：下单流程重构、优惠券叠加规则调整
- **支付网关**：新增微信支付 V3 接口兼容
- **用户中心**：会员等级体系改版

系统面向 C 端用户，日均 UV 约 50 万，QPS 峰值约 3000。本次迭代属于功能升级+回归类型，直接影响交易链路核心流程。

本文档定义电商平台 V2.5.0 版本的测试策略、范围、进度与资源安排，适用于 QA 团队内部执行及项目组同步对齐。

## 4. 测试策略

### 4.1 测试范围

**在测模块：**

| 模块 | 改动类型 | 测试重点 |
|------|----------|----------|
| 商品管理 | 功能优化 | SKU 批量导入成功率、上下架状态机流转 |
| 订单中心 | 流程重构 | 下单链路完整性、优惠券叠加计算准确性 |
| 支付网关 | 新增接口 | 微信支付 V3 双向鉴权、回调幂等处理 |
| 用户中心 | 改版 | 会员等级映射关系、老用户数据兼容 |
| 关联回归模块 | 回归 | 搜索推荐、库存扣减、消息通知 |

**不在测范围：**
- 第三方物流 API 内部逻辑
- 财务对账后台（本期未改动）
- 运维部署脚本（由运维专项验证）

### 4.2 测试类型

| 类型 | 方式 | 覆盖目标 |
|------|------|----------|
| 功能测试 | 手工 + 自动化 | P0/P1 用例全量覆盖 |
| 接口测试 | 自动化 (Newman) | 核心接口 100% 覆盖，非核心 ≥ 80% |
| 性能测试 | JMeter 脚本 | 下单/QPS ≥ 2000，P99 < 500ms |
| 兼容性测试 | 手动交叉 | Chrome/Safari/iOS/Android 主流版本 |
| 安全测试 | 基础扫描 | SQL 注入/XSS/CORS 白名单校验 |

### 4.3 测试方法

- **黑盒测试**为主，结合等价类划分、边界值分析设计用例
- **自动化优先**：所有回归类接口用 Newman 脚本覆盖，每日 CI 定时执行
- **探索性测试**：在每个迭代阶段预留 4h~8h 弹性时间做无脚本探索
- **A/B 比对**：涉及金额计算的场景，新旧结果逐一 diff

## 6. 测试通过标准

### 6.1 通过准则

| 指标 | 要求 |
|------|------|
| P0/P1 用例通过率 | ≥ 100% |
| P2 用例通过率 | ≥ 95% |
| P0/P1 缺陷 | 全部清零 |
| P2 缺陷 | ≤ 3 个且有规避方案、经技术/测试双签 |
| 接口自动化通过率 | ≥ 95% |
| 性能达标率 | 核心接口 P99 < 500ms，QPS ≥ 2000 |
| 代码覆盖率（核心链路） | ≥ 80% |

### 6.2 暂停/恢复准则

**暂停条件（任一满足即暂停测试）：**
- 冒烟测试不通过（核心链路阻塞 > 2 个）
- P0 缺陷 > 5 个且超过 48h 未修复
- 测试环境连续宕机 > 4h 未恢复

**恢复条件：**
- 阻塞问题已修复并验证通过
- 重新触发冒烟并通过
