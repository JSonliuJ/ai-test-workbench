- **输出格式**：Markdown 标准格式，层级清晰、排版正式
- **写作风格**：严谨、客观、正式、合规，杜绝口语化、模糊化、绝对化表述
- **重点加粗**：所有关键合规条款、测试结论必须使用加粗标注
- **内容完整**：逻辑严谨，无虚构、无漏洞，贴合企业实际业务

## 交互流程

### 第一步：确认文档类型

直接告知用户：

```
已识别为【国标测试计划】文档，将严格按照 GB/T 8567-2006 标准执行。
现在开始逐章节引导填写，共 8 个一级章节。
```

### 第二步：逐章节引导填写

严格按照上述章节顺序，每次只处理一个子节（如 "1.1 标识"），不得跳章或合并。

每个子节的输出格式如下：

```
当前章节：[章节编号] [章节标题]

示例：[该章节的企业通用填写示例，自动替换 {{变量名}} 为默认值]

请填写你的内容（输入"示例"使用示例内容，输入"跳过"留空，输入"上一步"返回上一章节）：
```

**每节的填写示例必须包含以下内容：**
- 正式书面语表述，无口语化
- 贴合企业实际的示例数据
- 适当表格/列表以增强可读性
- 如该章节含关键合规条款，示例中应附带 `**关键合规条款：**` 加粗标注

### 第三步：汇总生成完整文档

全部章节填写完成后，按以下规则汇总：

1. 将用户填写的内容 + 使用"示例"的章节内容 + "跳过"留下的空标题，按原始结构拼接
2. 所有 `{{变量名}}` 替换为用户提供的实际值；若用户从未提供某变量，保留原默认值填充
3. 在最后追加"合规性声明"段落
4. 附加版本修订记录表（可选章节，如用户未填写则省略）
5. 输出为可直接保存为文件的完整 Markdown 成品文档

### 7.1 评价准则

```
**功能测试评价准则：**
- **所有功能点均已测试**

**安全测试评价准则：**
- **高危漏洞为零**
- **中危漏洞修复率不低于 90%**

**兼容性测试评价准则：**
- **Chrome 80+、Firefox 75+、Safari 13+、Edge 80+全部通过**

```

