# AI-WEB 测试点分析生成规范

本文档定义 `web-testpoint` 的生成规则。最终页面文档和全局公共模块结构见 `testpoint-template.md`。
。

## 输入规则

- 优先使用用户给出的项目根目录；未给出时使用当前工作区根目录。
- 必须围绕一个明确批次号执行，例如 `20260602-215450`。
- 指定批次后，只读取匹配批次目录下的 `json/*.json` 和 `img/*`，不要额外读取其他批次。
- 同一个批次号出现在多个功能目录时，可以同时处理这些匹配目录。

## 分析原则

- 只写当前 `func` 的专属测试点。
- 页头、页脚、全局搜索、主导航、侧边栏等公共元素只引用全局公共模块，不在每个页面重复展开。
- 不把其他业务功能写入当前功能文档。
- 不臆造后端接口、数据库、具体路由实现或不存在的业务规则。
- 优先从 DOM 可见文本、控件类型、按钮/链接、输入框 placeholder、页面标题和截图中提取测试点。
- 每个测试点必须包含“操作”和“预期”；有输入时补充“数据”。

## 输出规则

- 页面测试点输出目录：对应功能目录下的 `测试点分析/`。
- 公共模块输出目录：项目根目录下的 `测试点分析/`。
- 公共模块文件名固定为 `00_全局通用模块.md`。
- 页面文件名：`{功能名}.md`。
- 只使用一个 `#` 一级标题作为中心主题。
- 使用 `##`、`###`、`####` 和 `-` 列表表达层级，不使用 Markdown 表格作为主体结构。
- 截图路径必须使用从输出文档到截图文件的相对路径。

## 公共模块策略

- 指定批次中有 2 个及以上页面共享相似页头、页脚、主导航、登录状态入口或侧边栏时，生成全局公共模块文档。
- 只分析单个页面且无法确认公共性时，可以在页面文档中写“本批次未单独生成全局公共模块”，不要展开大量公共测试点。
- 如果公共模块文档已存在，优先增量更新，不覆盖用户已有补充。
- 页面文档引用公共模块时，按页面文档位置计算到 `测试点分析/00_全局通用模块.md` 的相对路径。

## 常见页面补充项

- 登录页：账号为空、格式错误、未注册账号、密码为空、密码边界、错误密码、自动登录、重复点击、成功跳转、失败提示。
- 注册页：手机号为空、格式错误、已注册、密码为空、密码长度边界、验证码为空/错误/过期/刷新、注册成功/失败。
- 搜索页：关键词为空、特殊字符、超长关键词、有结果、无结果、结果分页、搜索入口跳转。
- 列表页：初始列表、空状态、单页、多页、翻页边界、筛选无结果、排序切换、列表项点击跳转。
- 高风险操作：上传、下载、支付、删除等必须覆盖权限、确认弹窗、失败回滚、重复操作、异常中断。

## 自检规则
- 文档层级清晰，主体没有表格。
- 截图相对路径可从 Markdown 文件位置打开。
- 页面文档没有把全局导航或其他功能的测试点展开为当前功能测试点。
- 功能测试点、状态测试点、边界条件、业务跳转均已覆盖。
- 未臆造接口、数据库、代码实现或不可见路由。
