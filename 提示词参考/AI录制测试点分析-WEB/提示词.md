## 技能名称
`web-record-testpoint-generate`
重点： 请使用中文沟通！！

## 技能描述
- 结合录制的WEB页面数据，生成测试点分析文档

## 参考文档
testpoint-spec.md：测试点生成规范，定义分析原则、覆盖要求、公共模块策略等。
testpoint-template.md：测试点文档模板，定义输出格式（标题层级、列表结构、操作/预期等）。
生成测试点分析文档时，必须同时遵循上述两个文件的约束。

## 一、输入与数据读取
- 用户必须指定**批次号**（例如 `20260608_01`），技能不得自行猜测或扫描其他批次。
- 如果用户没有提供目录或批次号，需要明确询问。
- 数据目录结构固定为：
  ```
  AI需求采集/
  └── <批次号>/
      └── <功能分类>/
          └── <页面名称>/
              ├── img/      # 截图
              └── json/     # DOM JSON 文件
  ```
- **DOM JSON 常见字段**：
  - `module`：模块名（缺失时用功能目录路径推断）
  - `func`：功能名（缺失时用页面标题、URL 或 JSON 文件名推断）
  - `desc`：页面或功能说明
  - `content` / `raw_content`：Playwright snapshot、页面文本、层级结构
  - `img`：截图路径（相对采集时间戳目录 `img/screenshot_X.png`）
- 所有 JSON 和 Markdown 文件按 **UTF-8** 读写。Windows PowerShell 显示乱码时，不代表文件错误，优先用 Python `encoding="utf-8"` 验证。

## 二、输出格式（Markdown 大纲）
- **只使用一个 `#` 一级标题**作为中心主题。
- 使用 `##` 作为一级分支。
- 使用 `###` 和 `####` 作为下级分支。
- 使用 `-` 列表表达叶子节点。
- **禁止使用 Markdown 表格**作为主要结构。
- **禁止大段说明文字**；每行尽量是一个可读节点。
- 测试点必须拆分为子节点：
  - 操作
  - 数据（可选）
  - 预期
  - 覆盖元素（可选）
- **每个测试点必须同时包含“操作”和“预期”**。

## 三、分析原则
### 3.1 内容边界
- 只写当前 `func` 的专属测试点。
- 页头、页脚、全局搜索、主导航、侧边栏等公共元素只引用 `测试点分析/00_全局通用模块.md`，不在每个页面重复展开。
- 不把其他业务功能写入当前文档。例如分析“登录”时，不展开“全部作品”“充值”“作家专区”等业务测试点，只将其识别为全局导航入口。

### 3.2 信息来源限制
- 不臆造后端接口、数据库、具体路由实现。
- DOM 中有 URL 时可作为页面来源记录；测试点里只描述跳转目标（如“跳转到注册页”）。
- 优先从 DOM 可见文本、控件类型、按钮/链接、输入框 placeholder、页面标题和截图中提取测试点。

### 3.3 各类页面强制覆盖要求
- **登录、注册、搜索、表单类页面**：必须覆盖空值、格式错误、长度边界、重复提交、验证码/密码显示规则、网络异常或服务异常提示。
- **列表、分页、筛选、排序类页面**：必须覆盖空列表、单页、多页、翻页边界、筛选无结果、组合筛选、数据格式。
- **上传、下载、支付、删除等高风险操作**：必须覆盖权限、确认弹窗、失败回滚、重复操作、异常中断。

## 四、全局公共模块策略
- 如果同一批次中有 **2 个及以上页面**共享相似页头、页脚、主导航、登录状态入口或侧边栏，则生成 `测试点分析/00_全局通用模块.md`。
- 如果只分析单个页面，可以在页面文档中写明“全局公共模块：本批次未单独生成，按当前页面 DOM 识别为公共区域”，但**不要展开大量公共测试点**。
- 页面文档引用公共模块时，按页面文档位置计算到 `测试点分析/00_全局通用模块.md` 的相对路径。
- 如果跨多个功能目录生成文档，仍然只维护项目级的公共模块文档，不要在每个功能目录重复生成。

## 五、完成报告格式
最终回复用简短中文说明，格式如下：
```
已生成 AI测试点分析文档。
批次号：...
输出格式：Markdown 大纲，适合导入思维导图
生成文件：
1. 测试点分析/00_全局通用模块.md
2. 测试点分析/用户模块/登录注册/注册.md
3. 测试点分析/用户模块/登录注册/登录.md
验证：扫描器仅读取指定批次，文档层级和截图相对路径已检查。
```
