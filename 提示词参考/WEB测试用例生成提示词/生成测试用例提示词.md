## 技能名称：
generate-web-testcase

## 技能描述
主要给你一个文件夹进行阅读，你需要根据文件夹中的文件，生成测试用例。

## 技能流程

1. **输入数据**：询问默认路径，默认从当前项目下的 `02-测试` 文件夹中读取“测试点分析”。
2. **生成测试用例**：依据下方规则和方法生成。
3. **输出结果**：询问用户要 **MD文档** 还是 **Excel**，默认 Excel 格式。  
   输出路径：当前项目下的 `02-测试/手工测试用例` 文件夹。

## 生成规则

- **重点**：功能测试，验证页面功能是否符合需求。
- **不包含**：界面测试、兼容性测试、响应式测试、性能测试、安全性测试、可用性测试。

## 用例设计方法

| 方法         | 说明                       | 适用场景               |
| ------------ | -------------------------- | ---------------------- |
| 等价类划分   | 将输入数据划分为有效/无效等价类 | 输入字段测试           |
| 边界值分析   | 测试输入边界条件           | 数值、日期、文件大小   |
| 因果图法     | 分析输入与输出的因果关系   | 复杂逻辑组合           |
| 状态转换法   | 分析系统状态转换           | 登录、支付等状态流程   |
| 场景法       | 基于业务流程设计测试场景   | 用户操作流程           |

## 测试用例字段

| 字段     | 说明                                 |
| -------- | ------------------------------------ |
| 用例编号 | 唯一标识                             |
| 模块     | 所属功能模块                         |
| 前置条件 | 执行用例前必须满足的状态             |
| 测试步骤 | 明确、无歧义、可重复的操作序列       |
| 预期结果 | 具体断言（页面提示、跳转、数据变化） |
| 实际结果 | （执行后填写）                       |
| 测试结果 | 通过/失败                            |
| 优先级   | P0/P1/P2/P3                          |

## 测试步骤规范

- **禁止使用模糊描述**（如“输入其他数据”“点击其他按钮”“输入一些无效值”）。
- **必须明确**：操作对象（按钮名称、输入框标签）+ 操作内容。
- **格式模板**：  
  `"<字段名>"<控件类型> <操作> <操作值>`  
  - 有具体数值时直接写，例如 `"用户名" 输入框 输入 testuser01`  
  - 无具体数值时使用 `{{描述性文字}}`，例如 `"用户名" 输入框 输入 {{正确的用户名}}`

**示例：**
```
1. "用户名" 输入框 输入 testuser01
2. "密码" 输入框 输入 wrongPwd
3. 点击"登录"按钮
```
```
1. "用户名" 输入框 输入 {{正确的用户名}}
2. "密码" 输入框 输入 {{正确的密码}}
3. 点击"登录"按钮
```

## 预期结果规范

- 具体页面提示、跳转
- 控件状态、数据变化或业务结果
- 多条断言分点列出

## 输出格式
一定按照我的模板进行输出，不能有任何偏差。
### 一、MD 文档（默认可选）

- **命名规范**：`<功能名>_测试用例.md`（如 `登录_测试用例.md`）
- **模板结构**：

```markdown
# <模块名>_<功能名> - AI-WEB用例

## 目录
当前测试用例的目录

## <测试标题>

### 用例信息

| 字段 | 内容 |
| ---- | ---- |
| 用例编号 | <用例编号> |
| 用例名称 | <测试标题> |
| 优先级 | <P0/P1/P2/P3> |
| 前置条件 | <前置条件> |

### 测试步骤

1. "<字段名>"<控件类型> <操作> <操作值>
2. ...

### 预期结果

- 具体断言1
- 具体断言2
```

- **多用例**：同一文件内可包含多个 `## <测试标题>`，每个标题下包含完整的用例信息、测试步骤和预期结果。
- **注意**：不保留 `<...>` 占位符；动态数据使用 `{{ 参数变量名 }}`。

### 二、Excel 格式（默认）

- 一个功能模块生成一个 **Sheet**，命名：`<功能名>_测试用例`（如 `登录_测试用例`）
- 列结构：

| 用例ID | 模块 | 测试场景 | 优先级 | 前置条件 | 测试步骤 | 预期结果 |
| ------ | ---- | -------- | ------ | -------- | -------- | -------- |
| TC_LOGIN_001 | 登录 | 正确的账号密码 | P0 | 已注册 testuser01/Pass1234 | 1. "用户名" 输入框 输入 testuser01<br>2. "密码" 密码框 输入 Pass1234<br>3. 点击"登录"按钮 | 跳转到首页，显示用户名 testuser01 |
