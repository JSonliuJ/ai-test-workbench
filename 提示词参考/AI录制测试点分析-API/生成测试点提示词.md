## 技能名称
`api-doc-generator`
重点： 请使用中文沟通！！

## 技能描述
- 结合录制的API数据，生成接口文档


## 参考文档
apidoc-spec.md：接口文档生成规范，定义分析原则、覆盖要求、公共模块策略等。
apidoc-template.md：接口文档模板，定义输出格式（标题层级、列表结构、操作/预期等）。
生成测试点分析文件时，必须同时遵循上述两个文件的约束。档时，必须同时遵循上述两个文件的约束。


## 接口文档生成规范（基于 api-record-cli 录制数据）

### 一、输入与数据读取

- **输入来源**：`api-record-cli` 工具录制的原始 JSON 文件。
- **数据读取**：从 raw JSON 中提取 API 相关字段（URL、method、params、body、headers、response.body 等）。

#### 输入 JSON 数据结构示例

```json
[
  {
    "request": {
      "id": "1848010049104",
      "method": "POST",
      "url": "http://logistics.hctestedu.com/v1/fleet/driver/ex?name=哈司机&sex=男&phone=15099998001&...",
      "headers": { "user-agent": "...", "accept": "...", "referer": "..." },
      "body": null
    },
    "response": {
      "status": 200,
      "headers": { "content-type": "application/json;charset=UTF-8", ... },
      "body": "{\"error_code\":0,\"success\":true,\"msg\":\"成功\",\"data\":{...}}"
    }
  }
]
```

### 二、字段映射表

| 分类                 | 子项            | 来源路径 / 说明                                              |
| -------------------- | --------------- | ------------------------------------------------------------ |
| **一、基本信息**     | 接口ID          | `uuid.uuid4().hex` 生成 32 位无横杠 UUID                     |
|                      | 请求名称        | 自动分析（基于 URL 路径与方法）                              |
|                      | 请求方法        | `request.method`                                             |
|                      | 请求路径        | `request.url` 中域名后的部分（不含查询参数）                 |
|                      | 完整 URL 示例   | `request.url`                                                |
|                      | 描述            | 自动分析（仅根据 path 与 method，不编造业务规则）            |
| **二、URL参数**      | 查询参数        | 从 `request.url` 中 `?` 后的部分解析并解码                   |
| **三、请求头参数**   | 请求头表格      | `request.headers` 中的字段                                   |
| **四、请求体参数**   | 请求体表格      | `request.body`（若为 JSON 则解析；否则保留原始格式）         |
| **五、响应（正常）** | HTTP状态码      | `response.status`                                            |
|                      | 正常响应头      | `response.headers`                                           |
|                      | 正常响应体格式  | `response.headers.content-type`                              |
|                      | 正常响应体参数  | 从 `response.body` 解析 JSON 后的字段                        |
|                      | 正常响应示例    | `response.body` 原始字符串，直接写入文档的代码块（如 5.1.4） |
| **五、响应（异常）** | 状态码 / 错误码 | 仅当 raw JSON 中存在真实异常响应（HTTP 4xx/5xx 或业务错误码）时提取 |
|                      | 消息            | 同上，严禁臆造                                               |

### 三、核心处理规则

| 类型         | 强制规则                                                     |
| ------------ | ------------------------------------------------------------ |
| **正常响应** | 必须从 raw JSON 的 `response.body` 中提取；未捕获到则标注“未捕获到响应体”，**禁止伪造 JSON** |
| **异常响应** | 仅当 raw JSON 中真实存在异常响应时才生成对应章节，**严禁脑补、臆测、编造** |
| **接口描述** | 仅基于 URL path 与 method 自动分析（如“获取司机列表”），不编造业务规则 |
| **参数说明** | 必须从 raw JSON 实际出现的参数名/值中归纳，不存在的字段绝不写入 |
| **示例值**   | 只能使用 raw JSON 中真实出现过的值，不允许构造示例           |
| **脚本位置** | 正式生成脚本统一放在 `scripts/` 目录（如 `api_doc_generator.py`），**禁止**在项目根目录或临时位置创建一次性脚本 |

### 四、执行流程

1. **用户指定批次号**（例如 `20260608_01`），技能**不得**自行猜测或扫描其他批次。
2. 若用户未提供目录或批次号，需**明确询问**。
3. 数据目录结构固定为：

   ```
   AI-接口采集/
   └── 20260609_01/
       └── raw01.json
   ```

4. 扫描该批次号对应文件夹下的所有 JSON 文件。
5. **去重**：对路径（path）和方法（method）完全相同的接口进行去重。
6. **分模块**：根据接口路径或业务语义自动划分模块。
7. 参考 `apidoc-template.md` 模板，生成接口文档。
8. 输出结构：

   ```
   AI-接口文档/
   └── 模块名/
       └── 模块名_接口文档.md
   ```

### 五、输出报告格式

生成完成后，输出如下格式的报告：

> 已处理批次号：`20260609_01`  
> 数据来源目录：`AI-接口采集/20260609_01/`  
> 发现原始接口数：`xx` 条（去重前）  
> 去重后接口数：`xx` 条  
> 模块划分：`模块A`（x个接口），`模块B`（y个接口）  
> 输出文档：  
> - `AI-接口文档/模块A/模块A_接口文档.md`  
> - `AI-接口文档/模块B/模块B_接口文档.md`
