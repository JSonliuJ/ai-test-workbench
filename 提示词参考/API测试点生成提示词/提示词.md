## 版本一：标准完整版（推荐，步骤清晰、交互引导）
### 提示词内容
请按照以下流程完成工作：
1. **询问用户数据来源**：主动向用户确认数据提供形式，可选两种：①接口URL地址 ②Swagger完整JSON文档数据
2. **接收数据**：根据用户提供的URL或Swagger JSON原始数据进行解析
3. **字段映射规则**：严格遵循下方【Swagger→接口文档映射规则】执行字段提取与赋值
4. **生成文档**：使用指定固定模板，逐条生成完整接口文档，一个接口对应一份独立文档，格式、字段、文案严格对齐要求

### 三、核心映射规则（强制遵守）
1. **基础信息映射**
- 接口ID：Swagger无对应字段，手动生成32位无横杠UUID
- 接口名称(中文_英文)：取`paths.[path].summary`作为中文，接口路径去除`/`作为英文，拼接格式：中文_英文
- 请求方法：提取paths下的`get/post`，转为大写
- 请求路径：直接取paths的key（如/balance）
- 完整URL示例：统一填写「待补充」
- 描述：基于`summary`语义扩展，说明接口用途

2. **URL参数（Query参数）**
- 参数名：提取`parameters[].name`
- 值：提取`parameters[].x-example`，无示例则填「待补充」
- 说明：提取`parameters[].description`

3. **请求头参数**
- Content-Type：GET接口填「待补充」；POST接口固定为`application/json`（取自`consumes`）
- Authorization：统一填写「待补充」

4. **请求体参数**
- 请求体类型：GET接口填「无」，说明为「GET请求，无请求体」；POST+application/json 填「JSON」，说明为「接口请求数据为JSON格式」
- 参数定义：本次所有接口参数均为Query参数，整行填写「无」
- 请求示例：固定内容 `// 待补充：请提供真实数据`

5. **正常响应**
- 响应头Content-Type：取自`produces`，固定为`application/json`
- 响应体格式：类型填「JSON」，说明填「接口返回标准JSON格式数据」
- 响应体参数：解析`definitions.ResponseEntity.properties`，字段包含：body(object)、statusCode(string)、statusCodeValue(integer)，并对应填写说明
- 正常响应示例：固定内容 `// 待补充：录制批次中未捕获到正常响应体`

6. **异常响应**
- 异常响应体格式：填「待补充」
- 异常响应体参数：所有字段填「待补充」
- 异常响应示例：固定内容 `// 待补充：录制批次中未捕获到异常响应`
- 异常响应状态码：固定3个场景：身份未授权(401)、权限不足(403)、接口不存在(404)；code、msg 统一填「待补充」

7. **补充说明**
- 所有接口独立拆分生成文档，不合并
- 表格、代码块格式严格保留，文案不得随意修改
